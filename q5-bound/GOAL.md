# Q5: чи окупається самочитання годиннику, який уже біля межі TUR?

## Звідки питання

У [Q4](../q4-line/REPORT.md) кристал, що читав себе через лінію роторів, став дешевшим годинником: η ×1,76 (0,45 проти 0,26), тепло лінії враховано. Але той кристал сам по собі марнотратний: його ціна йде на проковзування через пінінг.

Межа TUR каже, що жодна автономна система не дає η понад ≈ 1. Тож якщо кристал уже біля межі, ефективність купити нема де. Точність купити можна, але за повну ціну.

## Що змінено

- **Кристал.** Той самий, але при меншому терті γ = 0,5 (решта як у Q4). Він біжить зі швидкістю v ≈ 2,59 на фазу, η ≈ 0,9–1,1.
- **Лінія.** Та сама, що в Q4, без змін: тертя γ_line = 2, K = 2, L = 16. Вона читає кристал через **ідеальний редуктор** r = 5,307: ведучим для неї є Φ / r, який рухається так, як кристал Q4. Корекція: F(t) = F − k·(Φ − r·ψ_L − r·Λ*).
- **Чому редуктор.** Лінія з тієї самої матерії в тонкій ванні (γ_line = 0,5) не працює. Вона не встигає за такою швидкою фазою, а її недодемпфовані ротори резонують ступінь за ступенем і губять сигнал навіть без шуму й з плавним пуском (`calibration/lag.txt`, `stiff.txt`, `ramp.txt`).
  - Редуктор не має втрат і в ціну не входить.
  - Він підсилює шум лінії в одиницях фази кристала в r разів. Це частина фізики: повільна лінія читає швидкий годинник.

## Що показало калібрування (seeds з окремого простору імен, у вердикт не входить)

- **Кристал за тертям** (`alone.txt`): γ = 2 / 1 / 0,5 / 0,25 дають η = 0,30 / 0,51 / 1,08 / 1,11.
- **Лінія через редуктор при k = 0** (`gear.txt`) відстає на 7,99–8,07 рад, розкид 0,24 (n_s = 8) … 0,06 (n_s = 512).
- **Зареєстрований дизайн, проаналізований зареєстрованим аналізом** (`full-analysis.json`; 1024 траєкторії, k = 0,06). Це урок Q4: калібрувати інтервал, а не лише точку.
  - Через нього пороги H2 і H4 та поріг умови «біля межі» обрано до реєстрації.
  - Із первісними порогами H4 вийшла б inconclusive, а умова «біля межі» (η > 0,8) пройшла б із запасом лише 0,016.

## Гіпотези (`registration.json`)

| | твердження | правило (інтервал log10) |
|---|---|---|
| H1 | біля межі точність ще продається: з лінією n_s = 128 кристал дифундує щонайменше втричі менше | G(line-n128) вище log10 3 |
| H2 | біля межі ефективність уже не продається: з лінією n_s = 128 η_total менше ніж ×1,25 від кристала самого (у Q4 було ×1,76). **Питається лише кристала біля межі:** оцінюється, коли інтервал η(alone) вище 0,6 (у Q4 було 0,26) | η(line-n128)/η(alone) нижче log10 1,25 |
| H3 | легка лінія, що загострила марнотратний кристал (Q4, n_s = 8: ×4,5), кристал біля межі погіршує | G(line-n8) нижче 0 |
| H4 | біля межі важка лінія коштує більше, ніж дає: з n_s = 512 кристал щонайбільше на дві третини такий ефективний, як сам | η(line-n512)/η(alone) нижче −log10 1,5 |

Інтервали 95% беруться з 2000 повторних вибірок траєкторій, засіяних від id реєстрації. D — нахил дисперсії. η = v²/(D·Σ), де Σ — тепло кристала й лінії разом.

## Дизайн

- **Параметри:** 6 клітинок по 1024 траєкторії, контрольні точки 400 / 800 / 1800. k = 0,06 — та сама петльова підсилювальність, що k = 0,16 у Q4, бо тут dv/dF ≈ 2,06. τ буфера = 16,5.
- **Seeds:** H(id реєстрації ‖ раунд маяка ‖ назва клітинки), для лінії — ‖ `:line`.
- **Контролі в `tests/`:**
  - 16 синтетичних, серед них дві умови «біля межі»: далеко від межі, і біля межі лише за точкою;
  - runner з редуктором 1 і лінією у ванні кристала збігається з Q4 біт у біт;
  - лінія через редуктор відстає на L·arcsin(γ_line·v/(r·K));
  - наскрізний прогін.
- **Мутанти:** 16, усі вбиті на assertion.

## Що цей дослід не стверджує

- **Редуктор ідеальний і безкоштовний.** Справжній коштував би.
- **Лінія з матерії кристала в його ванні тут не працює зовсім.** Дослід питає про лінію Q4, а не про лінію, яка могла б жити в тонкій ванні.
- **Одне k, одна лінія, чотири розміри ступенів.**
- **«Біля межі» означає η ≈ 1 саме цього кристала.** Межа TUR для недодемпфованої динаміки не строга: калібрування бачило до 1,11.
